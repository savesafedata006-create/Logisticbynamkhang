📄 โฟลการทำงาน (Work Flow) — SOP/WI

หน้านี้สรุป “ลำดับขั้นตอนทำงาน” แบบละเอียด แยกเป็นช่วง/บท พร้อมระบุ ใครทำ (Role), เอกสารที่ใช้, ผลลัพธ์ที่ต้องได้ และ จุดเสี่ยงที่ต้องเช็ค

Role-based เอกสาร/หลักฐาน Output กำหนดชัด Risk checkpoints

📑 สารบัญ (Click เพื่อเลื่อนไปส่วน)

SOP/WI
1) รับเคส/ตั้งค่าเริ่มงาน 2) ตรวจข้อมูลก่อนทำเอกสาร 3) ทำ Invoice + Validation 4) ทำ Packing List 5) ทำ Shipping Document (BL) 6) ทำ Export Document 7) ทวนสอบ/จัดเก็บ/ส่งมอบ 8) การรายงานงานเพิ่ม (คนขับ) 9) การคำนวณต้นทุน & ใบเสนอราคา 10) การบริหารกองรถ & การจัดรถ 11) การจัดการสิทธิ์ & ความปลอดภัย 8) Checklist เอกสารต้องมี

🧩 1) รับเคส/ตั้งค่าเริ่มงาน

Kickoff
1
รวบรวมข้อมูลเคสจากงาน/ฝ่ายที่เกี่ยวข้อง
Role: CS/ประสานงาน เอกสาร: RN/CB, Booking/DO (ถ้ามี) Output: เคสพร้อมทำเอกสาร
Risk: ข้อมูลไม่ครบ
  • ตรวจว่าได้เลขสำคัญครบ: RN, Container, ลูกค้า, ปลายทาง
  • บันทึก “สิ่งที่ยังรอ” แยกออกจากสิ่งที่พร้อมใช้แล้ว
  • กำหนด Timeline คร่าวๆ: วันที่ต้องส่งเอกสาร
2
ตั้งค่าระบบ/ค่ากำหนดบริษัทให้ถูกต้อง
Role: Documentation/Admin เอกสาร: ข้อมูลบริษัท, Tax ID Output: Header เอกสารถูกต้อง
Risk: Tax/ข้อมูลบริษัทผิด
  • ตรวจข้อมูลบริษัท: ชื่อ, ที่อยู่, โทร, อีเมล, Tax ID
  • ถ้ามีหลาย Exchange Rate ให้ยืนยัน “อัตราใช้งาน” สำหรับรอบนี้
  • หากมีการเปลี่ยนค่ากลาง ต้องบันทึกใน Settings ก่อนออกเอกสาร

🔎 2) ตรวจข้อมูลก่อนทำเอกสาร

Pre-check
3
ตรวจ “Master data” และความสัมพันธ์เอกสาร
Role: Documentation เอกสาร: Customer/Products/HS Database Output: เอกสารสร้างได้ทันที
Risk: HS Code/ลูกค้าไม่ตรง
  • ยืนยันว่าลูกค้ามีในระบบ (ชื่อลูกค้า + country + currency)
  • ยืนยันว่าทุกรายการสินค้า “มี HS Code” และมี Weight/Unit
  • ตรวจความเข้ากันของ Currency ระหว่างใบเอกสารกับสินค้า
4
ตรวจข้อมูลที่ส่งผลต่อการคำนวณ
Role: Documentation/Verifier เอกสาร: Invoice header, Transport type Output: ตัวเลข FOB/CNF/CIF น่าเชื่อถือ
Risk: น้ำหนัก 0 / สูตรคำนวณคลาดเคลื่อน
  • น้ำหนักต้องมากกว่า 0 และตรงกับหน่วยที่ใช้คำนวณ
  • ตรวจว่าเลือกประเภทการขนส่ง/เงื่อนไขให้ถูกต้อง
  • เช็ค duplicate product ว่าไม่ซ้ำในลิสต์สินค้า (ตาม validation)

🧾 3) ทำ Invoice + Validation

Invoice
5
สร้าง Invoice (เลือกประเภท/เลขที่/วันที่/ลูกค้า/สกุลเงิน)
Role: Documentation เอกสาร: Invoice No, Invoice Type, Customer Output: Invoice header พร้อม
Risk: เลขเอกสารซ้ำ
  • กรอก Invoice No, Invoice Date, เลือกลูกค้า, เลือก Currency
  • เลือกประเภท Invoice ที่ตรงกับเคส
  • เลือก transport type เพื่อให้ template/เงื่อนไขสอดคล้อง
6
เพิ่มสินค้า + ตรวจ HS/Weight/Currency/Duplicate
Role: Documentation เอกสาร: Items (Qty/Weight/Unit Price/HS Code) Output: Validation ผ่าน/แจ้งเตือนตามกติกา
Risk: HS Code ขาด / Weight = 0
  • ตรวจว่าแต่ละรายการมี HS Code (ห้ามบันทึกถ้าขาด)
  • Weight ต้องไม่เป็น 0 (ห้ามบันทึก)
  • ถ้า currency ของสินค้าไม่ตรงกับเอกสารให้ “แจ้งเตือน (Warning)”
  • ห้ามมีสินค้าชนิดเดียวกันซ้ำ (ตามกติกา duplicate validation)
7
คำนวณ FOB/CNF/CIF และตรวจยอดรวม
Role: Verifier เอกสาร: Total Weight, Items Total Output: Grand Total ถูกต้อง
Risk: สรุปยอดรวมผิด
  • ตรวจ Total Weight (kg) และ Grand Total
  • ตรวจว่าแสดงหน่วย/สกุลเงินถูกต้อง
  • ดูตัวอย่าง (Preview) ก่อนพิมพ์/ส่งต่อ
ตัวอย่างหลักฐานที่ควรแนบ
  • Screenshot/Print ของ Invoice Preview
  • บันทึกเลขเอกสารในทะเบียนเอกสาร (ตามระบบ Document Registry)

📦 4) ทำ Packing List

PL
8
สร้าง Packing List และจับคู่กับ Invoice
Role: Documentation เอกสาร: PL No, Customer, Items count Output: PL พร้อมพิมพ์
Risk: จำนวนรายการไม่ตรง
  • เลือกเลข PL และกำหนดลูกค้าให้ตรง
  • จำนวนรายการต้องสอดคล้องกับ Invoice items
  • ใส่หมายเหตุ (ถ้ามี) ให้ครบถ้วน
9
ทวนสอบก่อนส่งต่อแผนกพิมพ์/ส่งมอบ
Role: Verifier เอกสาร: PL Preview Output: ผ่านการตรวจ
Risk: รูปแบบ/การสะกดผิด
  • ตรวจชื่อ/ที่อยู่/หมายเหตุไม่เพี้ยนจากข้อมูลต้นทาง
  • ตรวจรูปแบบตาราง/จำนวนไม่ล้น/ไม่หาย

🚢 5) ทำ Shipping Document (BL)

BL
10
สร้าง BL และระบุ Consignee + CBM
Role: Documentation เอกสาร: BL No, Consignee, CBM/Weight Output: BL พร้อมพิมพ์
Risk: CBM/Weight ผิด
  • ระบุ BL No, Consignee ให้ตรงกับเคส
  • กำลัง/น้ำหนัก (CBM/Weight) ต้องถูกต้องตามข้อมูลขนส่ง
  • ใส่หมายเหตุ (ถ้ามี)
11
ทวนสอบความพร้อมก่อนออกเอกสารชุดสุดท้าย
Role: Verifier เอกสาร: BL Preview/Print Output: BL ผ่านตรวจ
Risk: เลข BL ไม่ตรงชุดเอกสาร
  • ตรวจเลข BL/วันที่/ผู้รับสินค้าไม่ผิดพลาด
  • ตรวจว่าสรุปข้อมูลสอดคล้องกับ PL และ Invoice

📤 6) ทำ Export Document

Export
12
สร้าง Export Doc และระบุปลายทาง/ผู้ส่งออก
Role: Documentation เอกสาร: Export No, Exporter, Country Output: Export Doc พร้อม
Risk: ประเทศปลายทางผิด
  • กรอก Exporter/ผู้ส่งออก
  • เลือกประเทศปลายทางให้ตรงเคส
  • ใส่หมายเหตุถ้ามี

✅ 7) ทวนสอบ/จัดเก็บ/ส่งมอบ

Final QA
13
ทวนสอบเอกสารชุดสุดท้ายและความครบถ้วน
Role: Verifier เอกสาร: ทุกหน้าที่เกี่ยวข้องในชุด Output: ชุดเอกสารถูกต้องพร้อมส่ง
Risk: เอกสารขาด/ข้อมูลไม่ตรง
  • ตรวจเลขเอกสารทุกฉบับ: Invoice/PL/BL/Export
  • ตรวจข้อมูลหลักที่ต้องเหมือนกัน: ลูกค้า, ประเทศ, currency, น้ำหนัก/จำนวน
  • บันทึกหลักฐานการตรวจ (เช่น ลายเซ็น/วันที่ตรวจ)
14
จัดเก็บไฟล์ + ส่งมอบ/อัปโหลด
Role: Documentation เอกสาร: PDF ที่พิมพ์/ไฟล์แนบ Output: ส่งมอบถึงผู้รับปลายทาง
Risk: ไฟล์ไม่ถูกฉบับ
  • ตั้งชื่อไฟล์ให้สื่อความ: DOCTYPE_No_Date.pdf
  • อัปโหลด/ส่งมอบพร้อมหมายเหตุการแก้ไข (ถ้ามี)
  • เก็บสำเนาไว้ในโครงสร้างโฟลเดอร์เดียวกัน
สถานะที่ควรบันทึกในระบบ
  • draft → completed (ผ่านตรวจแล้ว)
  • exported (ถ้าส่งออกแล้ว)
กรอบเวลาแนะนำ
  • Pre-check: ภายใน 1 วันหลังรับเคส
  • Draft ทำเอกสาร: ภายใน 1-2 วัน
  • Final QA + ส่งมอบ: อย่างน้อย 1 วันก่อนกำหนด

📝 8) การรายงานงานเพิ่ม (คนขับ)

Driver Task
1. คนขับรายงานงานเพิ่มผ่าน Mobile Portal

คนขับบันทึกประเภทงาน (เช่น เวลารอ, โหลด/ลงของเพิ่ม), RN ที่เกี่ยวข้อง, ระยะเวลา/จำนวน, รายละเอียด และค่าใช้จ่ายที่เสนอ

Role: Driver Input: ประเภทงาน, RN, ระยะเวลา, รายละเอียด, ค่าใช้จ่าย Output: รายงานงานเพิ่มในระบบ
2. ฝ่ายออฟฟิศตรวจสอบและอนุมัติ

ฝ่ายออฟฟิศ (Dispatch/Finance) ตรวจสอบรายงานงานเพิ่มจากคนขับในหน้า "ติดตามคนขับ" และดำเนินการอนุมัติ/ปฏิเสธ

💰 9) การคำนวณต้นทุน & ใบเสนอราคา (Quotation & Costing)

Finance & CS
1. ประเมินต้นทุนพื้นฐาน (Fleet Cost)

ทีมจัดรถระบุ ระยะทาง, อัตราสิ้นเปลืองน้ำมัน และค่าเบี้ยเลี้ยงคนขับ

2. คำนวณ Margin และราคาเสนอขาย (CS Pricing)

ทีม CS ปรับแต่ง Margin (%) เพื่อให้ได้ราคาที่แข่งขันได้และมีกำไร

🚛 10) การบริหารกองรถ & การจัดรถ (Fleet Hub)

Operations
1. การจัดรถ (Dispatch)

ใช้ระบบ AI แนะนำรถที่เหมาะสมที่สุดตามประเภทตู้ และคะแนน KPI ของคนขับ

2. การติดตามสถานะ (Tracking)

ตรวจสอบพิกัด Live GPS จากการเช็คอินของคนขับผ่าน Mobile Portal

👥 11) การจัดการสิทธิ์ & ความปลอดภัย (HR & Security)

Management
1. การกำหนด Role-Based Access Control (RBAC)

Admin/Boss กำหนดสิทธิ์พนักงานตามตำแหน่ง (CS, Finance, Dispatch, etc.)

2. การตรวจสอบประวัติ (Audit Logs)

Boss ตรวจสอบความผิดปกติผ่านหน้า Security Overview เช่น การล็อกอินผิดพลาดหรือการแอบดูรหัสผ่าน

🧾 12) Checklist เอกสารต้องมี (SOP/WI)

Must-have
รายการ เอกสาร หลักฐาน/หมายเหตุ
1 Invoice Preview/Print + วันที่ตรวจ
2 Packing List (PL) จำนวนรายการต้องตรง
3 Shipping Document (BL) Consignee/CBM ต้องถูกต้อง
4 Export Document ประเทศปลายทาง/ผู้ส่งออก
5 Registry/ทะเบียนเอกสาร บันทึกเลขเอกสาร + รอบการทำ
หมายเหตุ: หน้า SOP/WI นี้เป็น “แนวทางมาตรฐาน” สำหรับการทำงานแบบ Demo/ระบบเอกสารในโปรเจค คุณสามารถแก้ชื่อเอกสาร/ขั้นตอนให้ตรงกับ SOP จริงของทีมคุณได้ทันที
